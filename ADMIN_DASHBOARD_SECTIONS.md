# 🎯 Admin Dashboard Sections - Complete Implementation Guide

## Overview
This document describes the five new admin dashboard sections implemented for the Hot Stone Bath Booking System. All sections are fully protected by admin middleware and provide comprehensive management capabilities.

---

## 1. 🛁 BATH MANAGEMENT

### Access
- **Route**: `/admin/baths`
- **Name**: `admin.baths`
- **Protection**: Admin middleware required

### Features

#### A. Bath Listing with Filters
- **View all registered baths** with key information:
  - Bath name, owner, type (Menchu/Dotsho/Tshachu)
  - Location (Dzongkhag), price per session, max guests
  - Operational hours (opening/closing time)
  - Current status (Active/Pending/Suspended)
  - Number of active services

- **Filter Options**:
  - 🔍 Search by bath name or description
  - 📁 Filter by bath type (Menchu, Dotsho, Tshachu)
  - ✅ Filter by status (Active, Pending Verification, Suspended)
  - 👤 Filter by owner
  - 📍 Filter by location (Dzongkhag)

- **Summary Stats**:
  - Total baths count
  - Active baths count
  - Pending verification count
  - Suspended baths count

#### B. Edit Bath Details
- **What You Can Edit**:
  - Bath name and description
  - Bath type and location
  - Owner assignment
  - Pricing (per session, per hour)
  - Max guests capacity
  - Opening and closing times

- **Route**: `/admin/baths/{bath}/edit`
- **Name**: `admin.baths.edit`

#### C. Bath Status Management
- **Change Operation Status** between:
  - Active ✅ - Bath is operational
  - Suspended ⛔ - Bath temporarily unavailable
  - Pending Verification ⏳ - Awaiting admin review

- **View Bath Status**:
  - Current status badge
  - Verification date
  - Services count with approval status

#### D. Delete Bath
- **Permanently remove** a bath from the system
- **Route**: `POST /admin/baths/{bath}/delete`
- **Name**: `admin.baths.delete`
- **Confirmation Required**: Yes (modal confirmation)

### Database Integration
Uses existing models:
- `Bath` - Core bath information
- `BathService` - Services offered
- `User` - Owner information
- `Dzongkhag` - Location data

### Controller Methods
```php
manageBaths()        // List baths with pagination & filters
editBath()          // Show edit form
updateBath()        // Save bath updates
deleteBath()        // Delete bath
```

## 2. 💰 COMMISSION MANAGEMENT

### Access
- **Route**: `/admin/commissions`
- **Name**: `admin.commissions`
- **Protection**: Admin middleware required

### Features

#### A. Commission Dashboard Overview
- **Summary Statistics Display**:
  - 💵 Total Revenue: Overall booking revenue collected
  - 📊 System Commission (15%): Amount retained by platform
  - 👥 Owner Earnings (85%): Amount paid to bath owners

- **Commission Breakdown Table**:
  - Owner name and email
  - Number of completed bookings
  - Total revenue generated by owner's baths
  - System commission amount (15% of revenue)
  - Owner earnings amount (85% of revenue)
  - Payout status indicator

- **Top Earners List**:
  - Top 5 owners by revenue
  - Booking counts
  - Earnings/revenue comparison

#### B. Commission Report Generation
- **Period Options**:
  - 📅 **Daily**: Transactions from today
  - 📊 **Weekly**: Transactions from current week
  - 📈 **Monthly**: Transactions from current month

- **Report Details Include**:
  - Transaction ID and booking ID
  - Owner name
  - Transaction amount
  - Commission breakdown (15% system, 85% owner)
  - Payment method used
  - Transaction date/time
  - Transaction status

- **Report Stats**:
  - Total revenue for period
  - Total commission earned
  - Total distributed to owners
  - Average transaction amount
  - Transaction count

- **Export Option**: Print/download report

### Commission Calculation
```
Commission Rate: 15% (configurable in settings)
Formula:
  Total Revenue = Sum of all successful transactions
  System Commission = Total Revenue × 15%
  Owner Earnings = Total Revenue × 85%
```

### Controller Methods
```php
manageCommissions()           // Show commission dashboard
generateCommissionReport()    // Generate period-based reports
```

### Routes
- `GET /admin/commissions` - View commissions dashboard
- `GET /admin/commissions/report` - View commission reports

## 3. 📢 NOTIFICATIONS & MESSAGES

### Access Routes
- **Notifications**: `/admin/notifications` → `admin.notifications`
- **Messages**: `/admin/messages` → `admin.all-messages`
- **Protection**: Admin middleware required

### Features

#### A. Send System Announcements

**Recipient Selection**:
- 👥 **All Owners/Providers**: Send to all bath owners only
  - Count: Dynamic (fetched from database)
  
- 👨 **All Customers/Guests**: Send to all customers only
  - Count: Dynamic (fetched from database)
  
- 🌐 **All Users**: Send to everyone (owners + customers)
  - Count: Dynamic total user count

**Notification Content**:
- **Subject**: Short announcement title (max 255 characters)
- **Message**: Full announcement body (markdown supported)
- **Preview Pane**: Real-time preview of notification

**Quick Templates**:
- 🔧 System Maintenance Notice
- ✨ New Feature Announcement
- 📋 Policy Update Notice
- 🎉 Promotion/Special Offer

**Sending**:
- Confirmation dialog before sending
- Success message with recipient count
- TODO: Integration with notification system

#### B. View Messages from Users

**Message Overview**:
- View all messages from customers and owners
- Filter by read/unread status
- Display sender information and role
- Show associated booking ID
- View message timestamps

**Message Details Include**:
- Sender name and role (Customer/Owner)
- Booking reference
- Bath name
- Message preview (50 characters)
- Received date and time
- Read status

**Message Actions**:
- View full conversation
- Mark as read
- Quick reply option

### Controller Methods
```php
sendNotification()    // Send system notifications
viewMessages()        // Display messages list
```

### Database Integration
- `Message` model - Message storage
- `Booking` model - Message context
- `User` model - Sender information

## 4. ⚙️ SETTINGS

### Access
- **Route**: `/admin/settings`
- **Name**: `admin.settings`
- **Protection**: Admin middleware required

### Features

#### A. Admin Profile Management

**Editable Information**:
- ✏️ Full Name
- 📧 Email Address (unique validation)
- 📱 Phone Number
- 📍 Address

**Password Change** (Optional):
- Current password verification (TODO)
- New password with confirmation
- Leave blank to keep current password

**Route**: `POST /admin/settings/profile` → `admin.settings.profile`

#### B. System-Wide Settings

**Commission Rate**:
- Configure platform commission percentage (0-100%)
- Default: 15%
- Applied to all transactions

**Booking Limits**:
- Default max guests per bath
- Booking time limit (hours in advance)
- Example: 24 hours = bookings must be made 24 hours before session

**System Notifications**:
- Enable/disable system-wide notifications
- Toggle notification delivery

**Route**: `POST /admin/settings/system` → `admin.settings.system`

#### C. Bath Types Reference
- Display available bath types:
  - 🌊 **Menchu**: Hot spring bath type
  - ♨️ **Dotsho**: Traditional stone bath
  - 🏊 **Tshachu**: Pool-style bath
  
- Show count of active baths per type
- Reference only (managed by system admin)

### Settings Tab Navigation
1. **Admin Profile** - Personal information
2. **System Settings** - Platform configuration
3. **Bath Types** - Reference information

### Controller Methods
```php
showSettings()            // Display settings page
updateAdminProfile()      // Save profile changes
updateSystemSettings()    // Save system configuration
```

## 🔐 Security & Access Control

All five sections are protected by the **admin middleware** chain:
```php
Route::middleware(['auth', 'admin'])->group(function () {
    // All routes here require:
    // 1. User authentication (logged in)
    // 2. Admin role (user->isAdmin() == true)
});
```

**Unauthorized Access**:
- Non-admin users are redirected to home page with error message
- Unauthenticated users are redirected to login page
- Audit trail can be implemented for access attempts
